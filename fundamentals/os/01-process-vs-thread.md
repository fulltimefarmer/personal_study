# 题目：进程与线程的区别

## 问题
请详细说明进程（Process）与线程（Thread）的定义、核心区别、上下文切换开销、以及进程间通信（IPC）的常用方式。

## 考点
- 进程与线程的资源归属
- 上下文切换的流程与开销
- 多线程 vs 多进程的适用场景
- IPC（进程间通信）各种方式及其优缺点

## 解答

### 一、进程与线程的定义

**进程（Process）**：
- 正在运行的程序的实例，是**资源分配**的最小单位
- 每个进程拥有独立的地址空间（代码段、数据段、堆、栈）
- 进程间相互独立，一个进程崩溃不会直接影响其他进程

**线程（Thread）**：
- 进程内的执行单元，是**CPU 调度**的最小单位
- 同一进程内的线程共享该进程的地址空间（堆、全局变量、文件描述符等）
- 每个线程拥有独立的栈和寄存器上下文（PC、寄存器）

---

### 二、核心区别对照表

| 维度 | 进程 | 线程 |
|------|------|------|
| 资源 | 独立地址空间，资源独立 | 共享进程资源，栈独立 |
| 调度 | 由操作系统调度，切换开销大 | 由操作系统（或用户态调度器）调度，切换开销小 |
| 通信 | 需要 IPC（管道、消息队列、共享内存等） | 直接读写共享内存（但需同步） |
| 创建开销 | 大（需复制父进程地址空间或新建） | 小（共享进程地址空间） |
| 隔离性 | 强隔离，一个进程崩溃不影响其他 | 弱隔离，一个线程崩溃可能导致整个进程崩溃 |
| 独立性 | 可独立运行在不同机器上 | 必须依附于进程 |
| 系统调用 | `fork()` / `exec()` | `pthread_create()` / `std::thread` |

---

### 三、上下文切换（Context Switch）

**定义**：CPU 从一个进程/线程切换到另一个进程/线程时，保存当前上下文并恢复目标上下文的过程。

**线程切换**：
1. 保存当前线程的寄存器（PC、SP、通用寄存器）到 TCB（Thread Control Block）
2. 从目标线程的 TCB 恢复寄存器
3. 切换内存映射（线程切换通常不需要切换页表，因为同进程线程共享地址空间）

**进程切换**：
1. 保存当前进程的寄存器到 PCB（Process Control Block）
2. 切换页表（CR3 寄存器）、刷新 TLB
3. 从目标进程的 PCB 恢复寄存器
4. 进程切换需要切换地址空间，MMU 需要加载新的页表，**开销远大于线程切换**

**开销来源**：
| 操作 | 开销 |
|------|------|
| 保存/恢复寄存器 | 低 |
| Cache 失效（冷启动） | 高 |
| TLB 刷新（进程切换特有） | 很高 |
| 流水线冲刷 | 中 |

---

### 四、进程间通信（IPC）

| 方式 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **匿名管道（Pipe）** | 内核缓冲区，半双工，仅父子进程 | 简单 | 单向，仅限亲属进程 |
| **命名管道（FIFO）** | 文件系统节点，无亲缘关系也可以用 | 可跨无亲缘进程 | 仍为半双工 |
| **消息队列（Message Queue）** | 内核维护的消息链表 | 异步、可设置优先级 | 有大小限制，不适合大数据 |
| **共享内存（Shared Memory）** | 将同一物理内存映射到多个进程地址空间 | **最快**，适合大数据 | 需要同步机制（信号量） |
| **信号量（Semaphore）** | 计数器，控制多进程对共享资源的访问 | 可协调共享内存 | 本身不传递数据，仅做同步 |
| **信号（Signal）** | 异步通知机制（如 SIGKILL、SIGTERM） | 开销小 | 信息量少 |
| **Socket** | 网络/本地套接字 | 可跨网络，通用性强 | 相对较重 |

**速度排序**：共享内存 > 管道 > 消息队列 > Socket

---

### 五、多线程 vs 多进程选择

| 场景 | 推荐 | 原因 |
|------|------|------|
| 计算密集型 | 多进程 | 绕过 GIL（Python/Ruby），利用多核 |
| I/O 密集型 | 多线程/协程 | 线程切换快，I/O 等待不占 CPU |
| 需要高可靠性 | 多进程 | 单个进程崩溃不影响全局 |
| 需要大量共享数据 | 多线程 | 共享内存无需序列化，通信成本低 |
| 需要跨机器扩展 | 多进程 | 进程可部署在不同机器 |
| 浏览器 | 多进程 | Chrome 每个 Tab 一个进程，崩溃隔离 |

```java
// Java 多线程示例
Thread t = new Thread(() -> {
    System.out.println("Thread: " + Thread.currentThread().getName());
});
t.start();
t.join();   // 等待线程结束

// Java 进程
ProcessBuilder pb = new ProcessBuilder("echo", "hello");
Process p = pb.start();
```

```typescript
// Node.js Worker Threads（多线程）
import { Worker, isMainThread } from "worker_threads";

if (isMainThread) {
    const worker = new Worker(__filename);
    worker.on("message", (msg) => console.log("收到:", msg));
    worker.postMessage("hello from main");
}

// Node.js Child Process（多进程）
import { fork } from "child_process";
const child = fork("child.js");
child.on("message", (msg) => console.log("子进程消息:", msg));
child.send({ task: "compute" });
```

### 六、协程（Coroutine）补充

协程是更轻量级的执行单元，用户态调度，无需内核参与切换：

| 维度 | 线程 | 协程 |
|------|------|------|
| 调度者 | 操作系统内核 | 用户程序 |
| 切换开销 | 微秒级（内核态切换） | 纳秒级（函数跳转） |
| 并发数 | 几千个 | 数十万个 |
| 代表 | Java Thread | Go goroutine, Kotlin coroutine, JS async/await |

## 总结
进程是资源分配单位，线程是 CPU 调度单位。进程隔离性强、切换开销大，通过 IPC 通信；线程共享进程资源、切换快，通过共享内存通信但需要同步。计算密集用多进程，I/O 密集用多线程/协程。
