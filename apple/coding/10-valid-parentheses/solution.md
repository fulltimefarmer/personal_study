# Valid Parentheses — 考点分析与解题思路

## 考点分析

1. **栈的经典应用**：括号匹配是「后进先出」最直观的体现——后出现的左括号必须最先被匹配。用栈保存尚未匹配的左括号。
2. **匹配表**：用哈希表记录 `右括号 -> 对应左括号`，避免多层 `if/else`，代码更简洁且易扩展（如加入新括号类型）。
3. **提前返回**：遇到右括号时若栈为空（没有可匹配的左括号）或栈顶类型不匹配，直接返回 `false`，无需继续。
4. **边界**：字符串全为左括号（遍历结束后栈非空）、全为右括号（第一个就失配）。

## 解题思路

- 遍历字符串 `s`：
  - 遇到左括号：压栈。
  - 遇到右括号：若栈为空或栈顶不是对应的左括号，返回 `false`；否则弹出栈顶。
- 遍历结束后，栈为空即为有效（所有左括号都已被匹配）。

## 复杂度

- 时间：O(n)，每个字符进出栈各一次。
- 空间：O(n)，最坏情况全为左括号。

## 参考代码

```ts
function isValid(s: string): boolean {
  const map: Record<string, string> = { ')': '(', ']': '[', '}': '{' };
  const stack: string[] = [];
  for (const ch of s) {
    if (ch === '(' || ch === '[' || ch === '{') {
      stack.push(ch);
    } else {
      if (stack.length === 0 || stack.pop() !== map[ch]) {
        return false;
      }
    }
  }
  return stack.length === 0;
}
```

## 追问 / Follow-ups

1. **只有一种括号**（如小括号）且可判定？→ 计数器即可，无需栈。
2. **带 `*` 通配符的括号**（LeetCode 678 Valid Parenthesis String）？→ 贪心维护「最小/最大可能的左括号数」区间。
3. **最长有效括号**（LeetCode 32，Hard）？→ 栈存下标或双向 DP。
4. **输入包含非括号字符**怎么办？→ 先和面试官澄清：忽略还是判错（Apple 看重边界澄清）。
