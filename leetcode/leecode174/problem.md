# LeetCode 174. Dungeon Game（地下城游戏） — **困难**

## 考点
数组、动态规划、矩阵

## 题目描述
恶魔们抓住了公主并将她关在了地下城 `dungeon` 的**右下角**。地下城是由 `m x n` 个房间组成的二维网络。我们英勇的骑士最初被安置在**左上角**的房间里，他必须穿过地下城并通过对抗恶魔来拯救公主。

骑士的初始健康点数为一个正整数。如果他的健康点数在某一时刻降至 0 或以下，他会立即死亡。

有些房间由恶魔守卫，因此骑士在进入这些房间时会失去健康点数（负整数）；其他房间要么是空的（0），要么包含增加骑士健康点数的魔法球（正整数）。

为了尽快到达公主，骑士决定每次只**向右**或**向下**移动一步。

返回确保骑士能够拯救到公主所需的最低初始健康点数。

注意：任何房间都可能对骑士的健康点数造成威胁，也可能增加骑士的健康点数，包括骑士进入的左上角的房间和公主被监禁的右下角的房间。

**示例 1：**
```
输入：dungeon = [[-2,-3,3],[-5,-10,1],[10,30,-5]]
输出：7
解释：如果骑士遵循最佳路径：右 -> 右 -> 下 -> 下，则初始健康点数为 7。
```

**示例 2：**
```
输入：dungeon = [[0]]
输出：1
```

**提示：**
- `m == dungeon.length`
- `n == dungeon[i].length`
- `1 <= m, n <= 200`
- `-1000 <= dungeon[i][j] <= 1000`

## 解题思路

### 核心思路

从公主位置（右下角）逆向 DP 到骑士位置（左上角）。`dp[i][j]` 表示从单元格 `(i, j)` 出发到达终点所需的最小初始血量。每个位置至少需要 1 点血，且需要满足：进入下一格时的血量 + 当前格的变化值 >= 下一格所需血量。

### 算法步骤

1. 初始化 `dp[m][n]`，`dp[m-1][n-1] = max(1, 1 - dungeon[m-1][n-1])`
2. 填充最后一行：`dp[m-1][j] = max(1, dp[m-1][j+1] - dungeon[m-1][j])`
3. 填充最后一列：`dp[i][n-1] = max(1, dp[i+1][n-1] - dungeon[i][n-1])`
4. 从右到左、从下到上填充其余位置：
   `dp[i][j] = max(1, min(dp[i+1][j], dp[i][j+1]) - dungeon[i][j])`
5. 返回 `dp[0][0]`

### DP 表全视图

```
DP表最终状态：
           [0]    [1]    [2]
    [0]     7      5      2
    [1]     6     11      5
    [2]     1      1      6

最佳路径: → → ↓ ↓
(0,0)→(0,1)→(0,2)→(1,2)→(2,2)

路径追踪:
  起点血=7, 位置(0,0)得-2 → 剩余5
  →(0,1)得-3 → 剩余2
  →(0,2)得+3 → 剩余5
  ↓(1,2)得+1 → 剩余6
  ↓(2,2)得-5 → 剩余1 (刚好存活!)
```

### 边界情况

| 场景 | 输入 | 处理 |
|------|------|------|
| 1x1 网格 | `[[5]]` | dp[0][0] = max(1, 1-5) = 1 |
| 1x1 负值 | `[[-3]]` | dp[0][0] = max(1, 1-(-3)) = 4 |
| 全正值 | `[[1,2],[3,4]]` | dp 全为 1 |
| 全负值 | `[[-5,-5],[-5,-5]]` | 需要极高初始血量 |

### 复杂度分析

| 指标 | 值 | 说明 |
|------|-----|------|
| 时间复杂度 | O(m × n) | 填充整个 DP 表 |
| 空间复杂度 | O(m × n) | 可优化为 O(n) 用一维数组滚动 |
