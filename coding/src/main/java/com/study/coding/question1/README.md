# 题目 1：LRU 缓存（Least Recently Used）

## 题目描述

请你设计并实现一个满足 **LRU（最近最少使用）缓存** 约束的数据结构。

实现 `LRUCache` 类：

- `LRUCache(int capacity)` —— 以正整数作为容量 `capacity` 初始化 LRU 缓存。
- `int get(int key)` —— 如果关键字 `key` 存在于缓存中，则返回关键字的值，否则返回 `-1`。
- `void put(int key, int value)` —— 如果关键字 `key` 已经存在，则变更其数据值 `value`；如果不存在，则向缓存中插入该组 `key-value`。如果插入操作导致关键字数量超过 `capacity`，则应该**逐出最久未使用的关键字**。

函数 `get` 和 `put` 必须以 **O(1)** 的平均时间复杂度运行。

## 示例

```
输入：
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]

输出：
[null, null, null, 1, null, -1, null, -1, 3, 4]

解释：
LRUCache cache = new LRUCache(2);  // 容量为 2
cache.put(1, 1);   // 缓存：{1=1}
cache.put(2, 2);   // 缓存：{1=1, 2=2}
cache.get(1);      // 返回 1，1 变为最近使用
cache.put(3, 3);   // 缓存已满，逐出 key=2，缓存：{1=1, 3=3}
cache.get(2);      // 返回 -1（未找到）
cache.put(4, 4);   // 缓存已满，逐出 key=1，缓存：{3=3, 4=4}
cache.get(1);      // 返回 -1
cache.get(3);      // 返回 3
cache.get(4);      // 返回 4
```

## 解题思路

### 1. 核心数据结构选择

实现 O(1) 的 `get` 和 `put` 操作，需要同时满足：
- **O(1) 查找** → 使用 `HashMap` 存储 key 到 Node 的映射。
- **O(1) 插入/删除** → 使用**双向链表**维护访问顺序，链表头是最近访问的节点，链表尾是最久未访问的节点。

两者结合：HashMap 负责快速定位，双向链表负责维护顺序。

### 2. 设计原理

```
┌─────────────────────────────────────────────────┐
│                HashMap<K, Node>                   │
│  key1 → Node1    key2 → Node2    key3 → Node3   │
└──────┬──────────────────────┬────────────────────┘
       │                      │
       ▼                      ▼
  ┌─────────┐    ┌─────────┐    ┌─────────┐
  │  HEAD   │◄──►│ Node(1) │◄──►│ Node(3) │◄──►│  TAIL   │
  │ (dummy) │    │ val=1   │    │ val=3   │    │ (dummy) │
  └─────────┘    └─────────┘    └─────────┘    └─────────┘
      ▲                                              ▲
      │              MRU → → → → → LRU               │
```

使用**哨兵节点**（dummy head 和 dummy tail）可以统一边界处理逻辑，避免 `null` 检查。

### 3. 操作详解

**get(key)**：
1. 在 HashMap 中查找 key，不存在直接返回 `-1`。
2. 存在：将该节点从链表当前位置**移到头部**（表示最近被访问），返回值。

**put(key, value)**：
1. 若 key 已存在：更新 value，将该节点移到链表头部。
2. 若 key 不存在：
   - 创建新节点，加入 HashMap，插入链表头部。
   - 若超出容量：**删除链表尾部节点**（即哨兵 tail 的前驱节点），同时在 HashMap 中移除对应的 key。

### 4. 关键细节

| 要点 | 说明 |
|------|------|
| 哨兵节点 | head 和 tail 为虚拟节点，简化插入/删除的边界判断 |
| 线程安全 | 使用 `synchronized` 确保并发场景下一致性 |
| 泛型设计 | 支持 `K, V` 泛型，增强代码复用性 |
| 参数校验 | 构造函数对 capacity 做合法性检查 |
| 链操作封装 | `addToHead`、`removeNode`、`moveToHead` 等私有方法职责单一 |

### 5. 复杂度分析

- **时间复杂度**：`get` 和 `put` 均为 O(1)（HashMap 查找 O(1)，双向链表插入/删除 O(1)）。
- **空间复杂度**：O(capacity)，HashMap 和链表节点数与容量成正比。
