# 题目 6：大文件单词频率统计

## 题目描述

给定一个**超大文本文件**（例如几百 MB 甚至几 GB，无法完全加载到内存），统计其中每个单词出现的**频率**，返回出现频率最高的 **top K** 个单词及其词频。

要求：

- 内存占用必须可控，不能一次性将整个文件读入内存。
- 单词的定义：由**字母（a-z, A-Z）**组成的连续字符序列，忽略大小写，即 "Hello" 和 "hello" 视为同一个单词。
- 其他字符（数字、标点符号等）视为分隔符，不计入单词。
- 返回结果按**词频降序**排列，频率相同时按**字母序升序**排列。
- 支持指定返回前 K 个结果，K 可配置。

## 示例

```
输入文件 content.txt 内容：
"Hello world! Hello Java. Java, Java world."

topK = 2

输出：
[
    {word: "java",  count: 3},
    {word: "hello", count: 2}
]
```

## 解题思路

### 1. 核心挑战：内存限制

对于超大文件，核心问题是如何在**有限内存**下完成任务。主要策略：

| 挑战 | 解决方案 |
|------|----------|
| 文件太大无法一次读入 | 使用 `BufferedReader` 逐行读取，流式处理 |
| 所有单词的词频统计内存不足 | 如果词种数可控（例如 < 百万级），用 `HashMap`；如果词种数也超大，使用**外部排序 + 归并** |
| TopK 排序 | 使用**最小堆**（PriorityQueue），只保留 K 个元素 |

### 2. 整体流程

```
                     ┌───────────────┐
                     │  打开大文件    │
                     └───────┬───────┘
                             ▼
                  ┌──────────────────────┐
                  │ BufferedReader       │
                  │ 逐行读取 + 分词      │
                  │ 累积到 HashMap        │
                  └──────────┬───────────┘
                             ▼
                  ┌──────────────────────┐
                  │ 最小堆过滤 TopK      │
                  │ (PriorityQueue)      │
                  └──────────┬───────────┘
                             ▼
                  ┌──────────────────────┐
                  │ 堆中元素出堆排序     │
                  │ → 返回结果列表       │
                  └──────────────────────┘
```

### 4. TopK 最小堆设计

```
目标：从 N 个词中选出频率最高的 K 个

PriorityQueue 比较器规则：
  - 优先按词频升序（堆顶是频率最小的）
  - 频率相同时按字母序降序（堆顶是字母序最大的，这样小的留在后面）

算法：
  1. 遍历 HashMap 的每个 Entry
  2. 堆大小 < K → 直接加入
  3. 堆大小 == K → 与堆顶比较：
     - 当前词频 > 堆顶词频 → 弹出堆顶，加入当前
     - 当前词频 == 堆顶词频 && 当前字母序 < 堆顶字母序 → 弹出堆顶，加入当前
     - 否则跳过
```

### 5. 为什么优先使用 HashMap 而非 TreeMap？

- HashMap 插入 O(1)，TreeMap 插入 O(log n)。
- 在构建完 HashMap 后，只需一次 TopK 筛选，不需要 TreeMap 的有序性。
- 对于百万级词种，HashMap 效率远高于 TreeMap。

### 6. 进阶：如果词种数也非常大？

如果词种数超出可用内存（例如数十亿不同单词），需要借助**外部归并排序**：

1. 将文件均匀切分为若干小块。
2. 每块独立统计词频，将结果写入临时文件（按单词排序）。
3. 使用 K 路归并，合并所有临时文件的计数。
4. 从归并结果中选出 TopK。

### 7. 复杂度分析

- **时间复杂度**：O(N + M log K)
  - N 为文件总字符数（扫描）
  - M 为不同单词数（建堆）
  - K 为 TopK 参数
- **空间复杂度**：O(M + K)
  - HashMap 存储词频 O(M)
  - 堆存储 TopK O(K)
  - 单行文本缓冲 O(1)（相对文件大小）
