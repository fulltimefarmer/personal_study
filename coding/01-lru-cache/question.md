# 第 1 题：LRU 缓存（LRU Cache）

## 题目描述

设计并实现一个满足 **LRU（最近最少使用）** 缓存约束的数据结构。

实现 `LRUCache` 类：

| 方法 | 说明 |
|------|------|
| `LRUCache(capacity)` | 以正整数 `capacity` 作为容量初始化 LRU 缓存 |
| `get(key)` | 如果关键字存在于缓存中，返回该关键字的值，并把它标记为最近使用；否则返回 -1 |
| `put(key, value)` | 如果关键字已存在，更新其值并标记为最近使用；如果不存在，插入该键值对。若插入后缓存容量超限，则**淘汰最久未使用**的键值对 |

函数 `get` 和 `put` 都必须以 **O(1)** 平均时间复杂度运行。

### 示例

```text
lru = LRUCache(2)
lru.put(1, 1)
lru.put(2, 2)
lru.get(1)     -> 1
lru.put(3, 3)  # 淘汰 key=2
lru.get(2)     -> -1
lru.put(4, 4)  # 淘汰 key=1
lru.get(1)     -> -1
lru.get(3)     -> 3
lru.get(4)     -> 4
```

## 考察点

- 哈希表 + 双向链表的组合使用
- 双向链表节点增删的指针操作
- 用哨兵节点（dummy head/tail）简化边界处理

## 解题思路

LRU 的难点在于：既要 O(1) 查找（哈希表），又要 O(1) 维护"最近使用"顺序（链表）。

1. **哈希表** `cache` 存 `key -> Node`，实现 O(1) 定位。
2. **双向链表** 按访问顺序排列节点，头部是最近使用，尾部是最久未使用。
3. `get`/`put` 命中时，把节点从原位置摘除并移动到头部；容量超限时删除尾部节点。

用两个哨兵节点 `head`、`tail` 作为链表边界，可以避免对空链表/头尾节点的特殊判断。

### 复杂度

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| get | O(1) | O(1) |
| put | O(1) | O(1) |
| 总空间 | - | O(capacity) |
