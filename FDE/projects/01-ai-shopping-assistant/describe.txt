  乐高智能导购助手「小砖家」— 项目架构与调用链说明
══════════════════════════════════════════════════════════════════════

【项目概述】
  基于 Agentic RAG 架构的乐高商品智能导购与客服系统。
  125 款真实乐高商品数据，主推理使用 DeepSeek API，
  简单问题自动路由到本地 Ollama 节省费用。

  技术栈：DeepSeek + Ollama(qwen2.5:3b) + ChromaDB + LangGraph + FastAPI + Vue 3

二、项目调用链
══════════════════════════════════════════════════════════════════════

【链路 A：数据入库 (ingest)】
  main.py:cmd_ingest()
    → ProductDataLoader(CSV路径)
        → load_clean()              解析CSV → 去重 → 清洗 → DataFrame
        → build_embed_docs()        每行商品 → 嵌入文本 + 元数据
    → ChromaStore()
        → delete_collection()       清空旧数据
        → add_documents(docs)       写入向量库
          → get_embeddings()        获取 bge-m3 嵌入模型
          → Chroma.add_documents()  LangChain → ChromaDB 底层写入


【链路 B：固定 RAG 查询 (query)】
  main.py:cmd_query()
    → _route_intent(question)       意图路由（闲聊/无效→预设回复）
      → classify_intent()           规则引擎分类
      → get_intent_response()       非商品咨询直接返回
    → RAGChain.query(question)
        → _retrieve(query)
          → expand_query()          同义词扩展
          → detect_age_intent()     年龄意图解析
          → detect_price_intent()   价格意图解析
          → ChromaStore.search() 或 search_hybrid()  向量检索
        → _format_docs(results)     检索结果 → LLM 可读上下文
        → RAG_PROMPT.format()       Prompt 模板填充
        → LLM.invoke()              大模型生成回答


【链路 C：Agentic RAG 查询 (agent)】
  main.py:cmd_agent()
    → _route_intent(question)       意图路由
    → run_agent(question, session_id)
        → get_memory(session_id)    获取/创建会话记忆
        → memory.get_context()      摘要 + 最近消息 → 上下文
        → _graph.invoke(initial_state)  执行 LangGraph 工作流:
            ┌────────────────────────────────────────────────┐
            │  START → agent_node → [有 tool_calls?]         │
            │     ↑        │              │                  │
            │     │        └── 无 ──────→ END                │
            │     │              │ 有                         │
            │     └── tool_node ←┘                           │
            │          (ToolNode 并行执行工具)                │
            │  最多循环 MAX_TOOL_CALLS=5 次                   │
            └────────────────────────────────────────────────┘
            agent_node: SystemPrompt + 历史 → LLM 决策
            tool_node:  提取 tool_calls → 调用 @tool 函数 → ToolMessage
            _should_continue: AIMessage 有 tool_calls? → 继续/结束
        → _extract_sources()         从 ToolMessage 提取来源
        → apply_guardrails()         4步幻觉防控流水线
        → memory.add_round()         更新会话记忆
        → return {answer, messages, tool_calls_log, sources, guardrails}


【链路 D：对比评测 (compare)】
  main.py:cmd_compare()
    ├─ [固定 RAG]
    │   RAGChain.query() → 结果 + apply_guardrails()
    └─ [Agentic RAG]
        run_agent() → 结果 + 内置 guardrails
    → 输出：回答对比 + 耗时 + 幻觉防控状态 + 工具调用次数


【链路 E：幻觉防控流水线 (guardrails, 在 run_agent / compare 内调用)】
  apply_guardrails(answer, sources, query)
    ├─ Step1: 无结果检查 → 检索为空 + 回答像推荐? → 标注警告
    ├─ Step2: 溯源校验   → 回答中商品名是否都在检索结果中?
    ├─ Step3: 来源标注   → 在回答末尾追加 📦 参考商品来源（含SKU/价格/匹配度）
    └─ Step4: 相关性检查 → 回答与问题的关键词重叠度 > 5%?


【链路 F：记忆管理 (memory, 在 run_agent 内自动触发)】
  ConversationMemory 内部:
    ┌──────────────────────────────────────┐
    │  full_history (完整历史)              │
    │  ┌────────────┬────────────────────┐ │
    │  │ summary    │ recent (最近N条)    │ │
    │  │ (旧消息压缩)│                    │ │
    │  └────────────┴────────────────────┘ │
    └──────────────────────────────────────┘
    触发条件：len(full_history) > max_total(默认30)
    压缩方式：LLM 将前半历史摘要为2-3句（失败则降级为拼接）
    输出：get_context() → [摘要SystemMessage] + recent_messages

四、核心设计决策
══════════════════════════════════════════════════════════════════════

  1. 固定 RAG vs Agentic RAG
     固定RAG：检索→格式化→生成，一次调用，快但不够灵活
     AgenticRAG：LLM自主决定是否检索、用什么工具、检索几次，慢但更准

  2. 混合排序
     语义相似度(55%) + 年龄匹配(20%) + 价格匹配(25%)
     L2距离用 1/(1+distance) 归一化为 [0,1] 相似度

  3. 两级记忆
     Level1 滑动窗口：保留最近 10 条消息保证即时连贯
     Level2 摘要压缩：超过 30 条时 LLM 压缩旧消息

  4. 意图路由
     规则引擎（非 LLM）：优先级 off_topic > chitchat > product_inquiry
     强 off-topic 信号(政治/编程/医疗/手机)直接拒绝，不消耗 LLM

  5. 幻觉防控 4 步流水线
     无结果检查 → 溯源校验 → 来源标注 → 相关性检查
